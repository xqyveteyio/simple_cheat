# Simple Cheat

Minecraft 1.20.1 的纯客户端 Fabric 模组，用来降低单人游戏难度。目前实现了「杀戮光环」（KillAura）。

服务端不需要安装。

## 环境要求

- Minecraft 1.20.1
- Fabric Loader 0.15.0 或更高
- [Fabric API](https://modrinth.com/mod/fabric-api) 0.92.x（1.20.1 版本）
- Java 17 或更高

## 安装

1. 用 [Fabric 安装器](https://fabricmc.net/use/installer/)为 1.20.1 安装 Fabric Loader。
2. 把 Fabric API 的 jar 放进 `.minecraft/mods/`。
3. 把 `build/libs/simple-cheat-1.0.0.jar` 也放进 `.minecraft/mods/`（不要放 `-sources.jar`）。

## 按键

| 按键 | 作用 |
| --- | --- |
| `R` | 开关杀戮光环 |
| `B` | 开关远程防护 |
| `V` | 开关自动闪避 |
| `G` | 开关自动搭路 |
| `右 Shift` | 打开设置界面 |

这些按键都可以在游戏内「选项 - 控制 - 按键绑定」的 Simple Cheat 分类里改。

设置界面里：左键点模块名切换开关，右键点模块名展开设置；开关类设置左键点击切换，多选类设置左键下一项、右键上一项，数值类设置左右拖动滑条。鼠标悬停在设置上时，面板底部会显示该项的说明。所有改动在关闭界面时自动存到 `.minecraft/config/simple-cheat.json`。

## 杀戮光环设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 攻击距离 | 4.0 | 眼睛到目标碰撞箱的距离，原版手动攻击是 3.0 |
| 攻击节奏 | 等待冷却 | 等待冷却每次都是满伤害；固定 CPS 更快但每下伤害低 |
| 每秒攻击次数 | 8 | 仅固定 CPS 节奏下生效 |
| 目标优先级 | 距离最近 | 可选距离最近、血量最低、视线最近 |
| 同时攻击多个目标 | 关 | 开启后一 tick 内攻击多个目标，代价是每下都不满伤害 |
| 转向方式 | 静默转向 | 静默转向只把朝向发给服务端，你的视角不会动；也可以选择不转向或真实转动视角 |
| 跳过无敌帧目标 | 开 | 见下方说明 |
| 需要视线 | 开 | 关闭后可以隔墙攻击 |
| 挥手动画 | 开 | 关掉只是没有动作，伤害照常 |
| 打开界面时暂停 | 开 | 打开背包、箱子时停止攻击，聊天框除外 |
| 使用物品时暂停 | 开 | 吃东西、拉弓、举盾时不攻击 |

目标类型分别有独立开关：敌对生物（默认开）、动物、玩家、村民与傀儡、已驯服的生物、盔甲架、其他生物（默认都关）。玩家目标会自动跳过同队玩家和创造/旁观模式的玩家。

### 关于无敌帧

原版里生物挨打后有 0.5 秒无敌帧，期间同等伤害的攻击会被 `LivingEntity#damage` 直接判定为无效，既不掉血也不击退。所以提高 CPS 并不能提高实际输出或击退频率，击退频率的上限就是每秒 2 次。

「跳过无敌帧目标」会在攻击前检查目标的 `hurtTime`，正处在无敌帧里就跳过，把这次攻击让给别的目标。配合「同时攻击多个目标」，面对一群怪时会自动轮着打而不是把攻击浪费在同一只身上。

顺带一提，「固定 CPS」在打单个生物时几乎总是比「等待冷却」差。攻击伤害要乘以冷却进度系数 `0.2 + h² × 0.8`，以钻石剑为例，等待冷却约 11.2 DPS，固定 8 CPS 只有约 3.2 DPS，而且拿不到冲刺攻击的额外击退（那需要冷却进度超过 0.9）。它主要适合一击能秒杀的场合，比如刷怪塔里清小怪。

## 远程防护设置

对付骷髅、女巫、恶魂这类远程敌人。需要手上有盾牌，优先用副手的，副手没有才用主手。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 举盾方式 | 检测到威胁时 | 常驻举盾会让移动速度只剩 20% 且无法冲刺，一般不建议 |
| 投射物飞来时 | 开 | 检测速度方向指向你的箭、火球、药水 |
| 敌人瞄准时 | 开 | 骷髅拉弓、掠夺者装填弩时就提前举盾 |
| 附近有远程敌人时 | 关 | 范围内有远程敌人就举盾，最保险但最影响移动 |
| 威胁检测距离 | 24 | 在多远范围内寻找威胁 |
| 自动面向威胁 | 开 | 盾牌只挡面朝的半边，用静默转向对准，不动你的视角 |
| 威胁解除后保持 | 10 | 单位 tick，避免盾牌频繁开合 |
| 优先击杀远程敌人 | 开 | 让杀戮光环把进入攻击范围的远程敌人排到最前面 |

### 盾牌的几个硬限制

这些都是原版机制，模组绕不过去：

- 举盾后要满 5 tick（0.25 秒）才真正生效，所以必须提前预判，这就是「敌人瞄准时」这个选项存在的原因——骷髅拉满弓要 20 tick，提前量足够。
- 盾牌只挡面朝的那半边（`blockedByShield` 里对朝向做点积判断），而且判断用的是服务端记录的朝向，所以「自动面向威胁」实际是靠静默转向实现的。
- 穿透附魔的弩箭直接无视盾牌。
- 拿斧头的敌人攻击有概率破盾，破盾后盾牌进入 5 秒冷却，这期间模块不会尝试举盾。

### 为什么能边举盾边攻击

原版举盾时不能攻击，是客户端在 `MinecraftClient.handleInputEvents` 里把左键事件空转吃掉了，服务端并不检查这个。杀戮光环直接调 `interactionManager.attackEntity`，不走那段输入处理，所以两个模块可以同时工作。

相应地，杀戮光环的「使用物品时暂停」对举盾开了例外：吃东西、拉弓时照常暂停，举盾时不暂停。

## 自动闪避设置

和远程防护相互独立，可以同时开。区别在于盾牌是「挡」，闪避是「让」，前者对近距离更可靠，后者能处理盾牌挡不住的情况（穿透弩箭、前后夹击、破盾冷却）。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 提前反应时间 | 20 | 单位 tick，预计命中还剩这么多 tick 时开始躲，调大会更早开始走位但也更容易乱走 |
| 只躲得干净才躲 | 开 | 算不出能全部躲开就干脆不动；关掉后只要能少挨一下就会走位 |
| 躲避时冲刺 | 开 | 移动更快更容易躲开，代价是消耗饥饿值 |
| 安全检查 | 开 | 不往悬崖、岩浆、火、仙人掌、细雪的方向躲 |
| 最大允许落差 | 3 | 躲避路上最多允许下落几格，超过 3 格才开始摔血；设成 0 就只在纯平地躲 |
| 允许前后闪避 | 开 | 左右都躲不开时再尝试前后 |
| 仅在地面上 | 开 | 空中横移效果差且容易摔下去 |
| 只躲有伤害的 | 开 | 忽略鱼钩、雪球、鸡蛋等打不掉血的投射物 |

### 原理

箭射出之后的运动完全没有随机成分，`PersistentProjectileEntity#tick` 每 tick 只做三件事：速度乘 0.99、纵向减 0.05、位置加速度。随机只发生在发射瞬间（骷髅那句 `setVelocity(..., 1.6F, 14 - difficulty * 4)`，困难难度散布值只有 2）。所以箭一旦生成，客户端就能逐 tick 精确推演它的轨迹。

判断命中用的是把你的碰撞箱外扩 0.3 格后做线段相交，和原版 `ProjectileUtil#getEntityCollision` 的 `margin` 参数一致。于是你的有效受击宽度是 0.6 + 0.6 = 1.2 格，横向挪开约 0.6 格就能让箭走空。

选方向时不是简单往旁边闪，而是对每个候选方向都重新推演一遍「我这样躲之后，全部来袭投射物里还有几个会打中我」，取命中数最少的那个，所以多支箭同时飞来时不会躲开一支又撞进另一支。命中数相同时优先顺着你当前的移动方向，减少方向突变。

「只躲得干净才躲」决定了怎样的结果算可接受：开启时要求推演结果一个都打不中，否则宁可站着不动；关闭时只要能比站着不动少挨一下就会走位。默认开启，因为躲一半通常是最差的选择——移动被接管了，伤害还是吃到了。

移动是靠 `KeyBinding#setPressed` 模拟按键实现的——原版的移动输入本身就是从按键状态读的（见 `KeyboardInput#tick`），所以走的是完全正常的移动流程，服务端看到的是一次合法移动，不需要改速度也不需要 mixin。模块每 tick 会把自己动过的按键还原成键盘上的真实状态，不会把你按住的键吃掉。

### 什么时候躲不掉

时间窗口取决于距离。骷髅箭初速 1.6 格/tick，玩家走路约 0.215 格/tick、冲刺约 0.28：

- 15 格外射来：箭飞约 10 tick，够横移 2 格有余，稳躲
- 8 格外：约 5 tick，算上起步加速大概能挪 0.6 到 1 格，勉强
- 5 格以内：约 3 tick，挪不够 0.6 格，躲不掉

近距离恰好是盾牌最稳的场合，所以两个模块一起开互补性最好。另外三种情况也会放弃闪避：安全检查判定所有方向都危险、你在空中或骑乘状态、以及算下来怎么躲命中数都不比站着不动少。这几种情况 HUD 会显示红色的「无法闪避」。

### 地形与落差

安全检查是沿整条躲避路径采样的，不是只看落点——躲避会持续好几 tick，最远可能走出 4 格，只检查一个点的话，两格外是平地、四格外是悬崖的地形照样会走下去。采样间隔 0.5 格，窄坑也漏不掉。

每个采样点会向下一路找落脚点，落差超过「最大允许落差」就当悬崖否决掉。水算安全落点，因为能接住人且不摔伤。判断是否有支撑用的是碰撞形状而不是「是不是空气」，所以草、火把这种看着有东西、实际站不住的方块不会被误判成地面。

台阶方向上，碰撞箱顶部低于抬腿高度（`getStepHeight`，默认 0.6）的矮方块，比如半砖，可以直接走上去，不算挡路；一格高的完整方块需要跳跃才能上去，而闪避不会自动跳，所以会被当成墙否决。

需要注意的是，落差会让预测精度下降：推演玩家未来位置时假设的是水平移动，如果躲避途中掉下去了，实际高度和推演的会有出入。想要最准的预测就把「最大允许落差」设成 0，代价是可用的躲避方向变少。

## 自动搭路设置

在脚下自动放方块，走到哪铺到哪。默认按 `G` 开关。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 预测落点 | 开 | 按移动速度提前在前方铺路，走快了不容易踩空 |
| 预测提前量 | 4 | 落点往前推算几 tick，跑跳时调大一些更不容易断 |
| 每 tick 最多放置 | 2 | 跑跳时一 tick 可能缺不止一格，调大能跟得上 |
| 塔式上升 | 关 | 开启后上升过程中也铺，按住跳跃就能原地往上叠；关掉则平地跳跃不会乱放 |
| 转向方式 | 静默转向 | 服务端不校验放置朝向，转向只是让动作自然一点 |
| 只用安全方块 | 开 | 跳过沙子、TNT、箱子、冰这类会掉落、爆炸、开界面或站不稳的方块 |
| 放完切回原槽位 | 开 | 不打断你原本拿在手上的东西 |
| 潜行时暂停 | 开 | 想主动下去的时候按住潜行即可 |
| 放置间隔 | 0 | 两次放置之间等待几 tick |

### 原理与限制

服务端处理放置请求时（`ServerPlayNetworkHandler#onPlayerInteractBlock`）只校验三件事：眼睛到方块中心不超过 6 格、命中点在方块中心 ±1 格以内、以及该位置有建筑权限。**它完全不检查玩家朝向**，所以搭路不转视角也能成功，「静默转向」纯粹是让动作看起来正常。

放方块必须点在一个已经存在的方块的面上，所以模块会在目标格的六个邻居里找一个能点的面，优先用水平方向的（搭路时身后那格刚铺好的路面），脚下和头顶最后才试。这也意味着**在完全孤立的空中放不出第一格**——周围六格全空时无解，得先站在有东西的地方起步。

斜着往上搭时，目标格经常只和已铺的方块对角相接，六个面全是空的。这种情况下模块会先在中间补一格跳板把两者连起来，下一 tick 再接着铺，所以搭出来的是阶梯而不是断开的对角线。「每 tick 最多放置」默认给 2 就是为了让跳板和目标格能在同一 tick 内完成。

### 为什么会「搭着搭着断掉」

这是最容易踩的坑，根源是一条容易被忽略的原版规则：

```java
// CollisionView#canPlace
return voxelShape.isEmpty() || this.doesNotIntersectEntities(null, voxelShape.offset(...));
```

**方块不能放在和实体相交的位置，包括你自己。** 站在平地上时脚底刚好贴着下面那格的顶面，边界接触不算相交，放得进去；可是一旦踩空开始下落，哪怕只掉了 0.08 格，脚下那格就和你的碰撞箱重叠了，放置会被直接拒绝——于是你继续掉，越掉越深，再也补不回来。拐弯时碰撞箱短暂移出支撑格，正好会触发这个死循环。

塔式上升是同一个问题的另一面：跳跃升到脚离地约 0.75 格时，目标格正好嵌在身体里，那几个 tick 全部放置失败；等升得够高能放了，如果还在奔跑，水平方向已经飘出去一两格接不上了。

模块现在从两头解决。一是**提前铺**：预测落点沿速度方向逐 tick 采样（而不是只算终点，否则走快了会跳过中间格），赶在踩空之前把前面的路铺好。二是**兜底**：万一还是踩空了，脚下那格放不进去时会往下退一格找落点，最多退 3 格。退一格照样接得住人，而且 3 格以内不摔血，比放弃不放好得多。

如果跑跳时还是偶尔会断，把「预测提前量」和「每 tick 最多放置」往上调。另外，原地塔式上升（不要同时奔跑）永远是最稳的，斜着往上跑对搭路的要求高得多。

方块选择会优先用你手上已经拿着的，没有再从快捷栏找。「只用安全方块」开启时的过滤条件是：不在黑名单里、不是重力方块（`FallingBlock`）、没有方块实体（排除箱子熔炉这类右键会开界面的）、且是完整立方体。黑名单额外挡掉了 TNT、工作台、音符盒、唱片机、史莱姆块、蜂蜜块、各种冰、岩浆块、灵魂沙、重生锚这些能站但不适合当路的。

切换槽位不需要自己发包，`ClientPlayerInteractionManager#interactBlock` 第一行就是 `syncSelectedSlot()`。

## 构建

```bash
./gradlew build
```

产物在 `build/libs/`。

开发时直接启动带模组的游戏：

```bash
./gradlew runClient
```

## 添加新模块

1. 在 `module/` 下新建一个类继承 `Module`，在构造函数里调用 `addSettings(...)` 注册设置项，重写 `onTick()` 写逻辑。
2. 在 `ModuleManager` 的构造函数里把它加进 `modules` 列表。

按键绑定、配置存取、设置界面、HUD 显示都会自动接上，不需要额外改动。

## 注意

这是个作弊模组，只建议在单人存档或自己的服务器上用。多数联机服务器禁止这类模组，可能会被封禁。
